3. Methodology written by AI

Red sent requests through a logging proxy to a test web application. Blue read only the proxy log after the traffic and labelled requests. A code-based judge scored the rounds. The designer checked attack labels for the audited results. Detection measures whether Blue flagged an attack, not whether it prevented success. The known attack types (SQL injection, cross-site scripting, path traversal) were tested separately from unrestricted traffic. Free-play, open-definition defender re-judged the same traffic as free-play, default defender; it was an analysis replay, not a new attacker interaction. The default prompt's false-alarm check and the open prompt's false-alarm check used held-back normal requests that had not been used for building or tuning. These checks tested the prompts without rules. Unaudited attacker labels are reported separately from checked labels.

Fixed facts (code): Red attacks a test web application through a logging proxy; Blue reads only the proxy log after the traffic, so it detects, it does not block; a deterministic Judge scores each round. Confidence levels follow rules fixed before any result was summarised: checked figures (attack labels checked by the designer, or normal requests known by construction) with at least twenty units are High, fewer are Moderate; unchecked attack labels are Low; the open-definition defender is capped at Moderate. 5. Key findings written by AI

Finding text by the AI; each finding's confidence is set by code: the lowest among the figures it cites.

F-01 · Checked known-type coverage did not establish broad coverage Moderate

The OpenAI known-type attacks were detected at 28/28 (100.0%) (95% CI 87.7–100.0%). Detection in free-play, default defender was 12/19 (63.2%) (95% CI 38.4–83.7%). The default defender recognised the checked known-type traffic but missed attacks in the broader sample. This separates recognition of familiar attack patterns from coverage of the attack space.

F-02 · The broader definition increased detection on the same traffic Moderate

Free-play, default defender contained 19 designer-checked attack attempts. Detection was 12/19 (63.2%) (95% CI 38.4–83.7%), compared with 14/19 (73.7%) (95% CI 48.8–90.8%) in free-play, open-definition defender. The change was +10.5 percentage points vs the default defender on the same free-play traffic. The added flags covered sensitive-data exposure requests. Directory and endpoint exploration still went unflagged, showing the remaining application-context gap.

F-03 · The default defender missed attacks that succeeded Moderate

In free-play, default defender, 7 attack attempts succeeded by solving a challenge. The default defender flagged 5/7 (71.4%) (95% CI 29.0–96.3%) and missed 2 successful attacks. Free-play, open-definition defender flagged 7/7 (100.0%) (95% CI 59.0–100.0%) on the same successful attacks. The missed successes involved sensitive-data exposure outside the default definition. Success counts refer to attack attempts, not the number of challenges solved.

6. Risk register written by AI

Prompt-scope blindness: Blue's attack definition is narrower than the attack space. Strong results on the known attack types do not establish broad attack detection. Application-context blindness: Blue does not know what the site links to, so forced browsing can read as ordinary traffic. Directory and endpoint exploration remained unflagged in free-play, open-definition defender. Structural blindness: some detection requires a user identity and knowledge of permissions, as in access-control checks. This was untested here; attacker-written technique labels do not establish that identity-dependent detection was tested. Operational risk: Open Blue has more false alarms and verdicts that vary run to run. The supplied figures do not quantify that variability. Layering leaves the combined queue's workload and handling effectiveness untested.

7. Deployment options written by AI

A retains Original Blue as a precise alert source with blind spots outside its known attack types. B uses Open Blue for wider coverage, with more false alarms and verdicts that vary run to run. C is Layered: original Blue supplies high-priority alerts, while open Blue supplies a low-priority review queue. C is untested. These arrangements express different alert-handling trade-offs, not a ranking.

9. Limitations written by AI

The frozen samples do not establish production-wide detection or false-alarm rates. Confidence labels and intervals accompany the reported figures. Replays reuse traffic and are not independent attacker campaigns. The prompt-only false-alarm checks do not measure a complete rules-enabled deployment. Reported AI costs cover model calls at the applicable provider prices, not total operating cost or analyst workload. The supplied evidence does not quantify run-to-run verdict variation. The layered arrangement and identity-dependent detection remain untested.

Default defender / original BlueThe defender as deployed in every match: it labels requests as one of the known attack types or as benign.
Open-definition defender / open BlueThe same defender with a wider attack definition (any attack), run afterwards on the same recorded traffic, for analysis only.
Free-playMatches in which the attacker could try any technique, not only the known attack types.
Succeeded / successful attackAn attack request that solved one of the test application's built-in challenges.
Checked (audited)The designer reviewed Red's attack labels, or judged whether each free-play request was an attack attempt; unchecked figures rest on Red's own labels.
False alarmA normal (non-attack) request the defender flagged as an attack.
Held-back normal requestsNormal requests set aside before any experiment and never used to build or tune anything.
Rule libraryDetection rules the defender wrote in earlier training matches and reuses read-only; a request a rule answers needs no AI call.
95% intervalThe range of rates compatible with the observed counts (exact binomial interval); small samples give wide intervals.
Percentage pointsThe difference between two percentages (e.g. from 60.0% to 70.0% is +10.0 percentage points).
Confidence (High / Moderate / Low)Set by code from fixed rules: checked figures with at least twenty units High, fewer Moderate; unchecked labels Low; the open-definition defender at most Moderate. A finding takes the lowest confidence of its figures.
